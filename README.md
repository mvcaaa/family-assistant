# Семейный ассистент в Telegram

Шлюз пускает в переписку только номера из списка и не отдаёт токен бота. Чужой чат и чужая заметка в запрос не попадают. Покупка, бронь, письмо, удаление, правка памяти и заход на сервер ждут одноразовую кнопку владельца. Кнопка живёт 10 минут и подтверждает одно действие.

Режим `bot` будит Grok Bot вебхуком. Ответ списывается из недельного лимита подписки SuperGrok. Режим `api` зовёт `api.x.ai` и платится отдельно. Телефонию, оплату и отправку писем программа не делает: после «да» ассистент может подготовить черновик.

## Что поставить один раз

Нужны Python 3.11 или новее и Telegram. Для режима подписки нужен Grok Bot на SuperGrok. Ключ на [console.x.ai](https://console.x.ai) нужен только для режима `api`.

1. В Telegram открой [@BotFather](https://t.me/BotFather), отправь `/newbot`, задай имя и имя пользователя. Скопируй токен. Затем `/setjoingroups` → Disable, чтобы бота нельзя было добавить в группу.
2. На console.x.ai создай API-ключ. Это не ключ от сайта grok.com.
3. В этой папке создай файл `.env` по образцу `deploy/env.example`.
   - `ALLOWED_PHONES` — номера семьи в международном виде, без плюса, через запятую. Пример для Финляндии: `358401112233`.
   - `OWNER_PHONE` — твой номер из этого же списка. Только он нажимает кнопки подтверждения.
   - Для первой проверки поставь `ASSISTANT_BACKEND=echo`. Бот повторит текст и не будет звать модель.
4. Запусти на своём компьютере:

```bash
cd family-assistant
PYTHONPATH=src python3 -m family_assistant --env .env
```

5. В Telegram открой бота. Первым пишет владелец: `/start`, кнопка «Поделиться номером». Потом то же самое с телефона каждого человека из списка. Чужой номер получит отказ, и бот не станет отвечать на его сообщения.
6. Напиши боту обычную фразу. В режиме `echo` ответ начинается с «Эхо:». Останови процесс через Ctrl-C.
7. Для настоящей работы поставь `ASSISTANT_BACKEND=bot` и пройди раздел «Режим подписки» ниже. Режим `api` остаётся запасным: впиши `XAI_API_KEY`, и голосовые начнут распознаваться. В режиме `bot` шлюз принимает текст.

Правила для модели лежат в `DATA_DIR/rules.md`. Файл создаётся при первом запуске, его можно править. Память, версии заметок и кнопки лежат в `DATA_DIR/assistant.sqlite`.

## Как этим пользоваться

Пиши текстом или голосовым в личный чат с ботом.

- `/memory` показывает заметку только этого человека.
- `/whoami` показывает, узнал ли бот номер.
- Владелец пишет `ревизия`. В этот запрос попадают заметки семьи, и модель может предложить замену. Пока кнопка не нажата, старый текст остаётся, а прошлая версия сохраняется.
- Раз в `REVIEW_DAYS` дней (по умолчанию 7) бот сам напоминает владельцу сверить память и ничего при этом не удаляет.
- Просьба купить, забронировать, написать кому-то, удалить или зайти на сервер превращается в кнопку в чате владельца. «Нет» и просрочка ничего не меняют. Повторно та же кнопка не срабатывает.

Общие правила редактируй в `rules.md`. Личные факты модель дописывает сама, короткой строкой, и только в заметку того, с кем сейчас говорит.

## Режим подписки

Каждое сообщение семьи будит одну routine Grok Bot. Ответ приходит не сразу: шлюз пишет «Передал», а текст появляется, когда Bot вызовет шлюз с пропуском. Пропуск действует `PASS_TTL` секунд (по умолчанию 15 минут), открывает один чат и одну заметку.

1. В Grok Bot создай routine. Триггер — webhook. В Instruction вставь `deploy/grok-bot-routine.md`. Сохрани и оставь routine включённой.
2. Открой routine на компьютере и скопируй **POST to** и **key**. Bot сам эти поля не показывает.
3. В `.env` поставь `ASSISTANT_BACKEND=bot`, `GROK_BOT_WEBHOOK_URL` и `GROK_BOT_WEBHOOK_KEY`.
4. Дай Bot адрес шлюза по https. На VPS шлюз слушает `127.0.0.1:8787`, снаружи его открывает обратный прокси:

```
family.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

`GATEWAY_PUBLIC_URL` — этот адрес, без слэша на конце. Локальный `http://127.0.0.1:8787` Bot из облака не видит.

Один запуск Bot тратит недельный лимит. У одной routine до 200 запусков в час. Голосовые в этом режиме не передаются: их понимает только режим `api`.

## Docker

Пуш в `main`, который меняет образ, собирает `linux/amd64` и `linux/arm64` и публикует `ghcr.io/mvcaaa/family-assistant` с тегами `latest` и `sha-<commit>`. На Apple Silicon берётся arm64. Секреты остаются в `.env` и в образ не попадают. Порт опубликован только на `127.0.0.1`, поэтому сам по себе хост не становится публичным.

Секреты лежат в vault `family-assistant` в 1Password. Файл `.env` собирается на ноутбуке и на диск TrueNAS попадает уже готовым. На NAS аккаунт 1Password не нужен.

```bash
op inject -i deploy/env.op.tpl -o .env
chmod 600 .env
docker compose up -d
curl -sS http://127.0.0.1:8787/health
```

Внутри контейнера шлюз слушает `0.0.0.0:8787`, данные лежат в томе `family-data`. `DATA_DIR` и `GATEWAY_HOST` из `.env` compose перекрывает.

Публичный адрес делается снаружи. Cloudflare Tunnel или Caddy на той же машине смотрит на `http://127.0.0.1:8787`. На этом hostname не включай Cloudflare Access и Bot Fight Mode: Grok Bot приходит обычным POST с пропуском и не проходит страницу входа.

## Сервер

Пока процесс запущен на ноутбуке, семья получает ответы, только если Grok Bot может открыть `GATEWAY_PUBLIC_URL`. Для круглосуточной работы процесс переносят на VPS. Приём Telegram идёт долгим опросом и не требует открытого порта. Ответ Bot требует https-адрес шлюза. Второй экземпляр с тем же токеном запускать нельзя: Telegram отдаёт обновления только одному получателю.

На сервере с systemd:

```bash
sudo useradd --system --create-home --home-dir /var/lib/family-assistant --shell /usr/sbin/nologin familybot
sudo mkdir -p /opt/family-assistant
sudo cp -a src deploy /opt/family-assistant/
sudo cp deploy/env.example /etc/family-assistant.env
sudo chmod 600 /etc/family-assistant.env
sudo chown familybot:familybot /var/lib/family-assistant
```

В `/etc/family-assistant.env` поставь `DATA_DIR=/var/lib/family-assistant`, токен Telegram и режим `bot` либо `api`. Потом:

```bash
sudo cp deploy/family-assistant.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now family-assistant
sudo systemctl status family-assistant
journalctl -u family-assistant -f
```

`Restart=always` поднимает процесс после падения. В логах нет текста сообщений и нет токена. Остановка: `sudo systemctl stop family-assistant`.

## Проверка без Telegram

```bash
cd family-assistant
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

Тесты проверяют допуск по номеру, изоляцию чатов и заметок, одноразовость кнопки и то, что токен бота не попадает в запрос к модели.
